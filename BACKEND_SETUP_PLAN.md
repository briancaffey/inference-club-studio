# Backend Setup Plan

## Overview

Set up a FastAPI + Celery backend for an audio/video processing application with agentic AI capabilities, fully containerized with Docker Compose.

---

## 1. Directory Structure

```
backend/
├── app/
│   ├── __init__.py
│   ├── main.py                  # FastAPI entrypoint, mounts routers, OpenAPI docs
│   ├── config.py                # Settings via pydantic-settings (env-driven)
│   ├── celery_app.py            # Celery app config
│   ├── routes/
│   │   ├── __init__.py
│   │   └── health.py            # Health check endpoint (starter route)
│   ├── tasks/
│   │   ├── __init__.py
│   │   └── example.py           # Starter Celery task
│   ├── clients/
│   │   └── __init__.py          # External service clients (future)
│   ├── utils/
│   │   ├── __init__.py
│   │   └── media.py             # ffmpeg/media helper stubs
│   ├── models/
│   │   └── __init__.py          # SQLAlchemy / DB models (future)
│   └── schemas/
│       └── __init__.py          # Pydantic request/response schemas (future)
├── tests/
│   ├── conftest.py              # Shared fixtures
│   └── test_health.py           # Starter test
├── pyproject.toml               # Dependencies, tool config (black, isort, flake8, pytest)
├── uv.lock                      # (generated by uv)
└── Dockerfile
```

## 4. Dockerfile

- Base image: `python:3.12-slim`
- Install system deps via apt
- Install `uv` for fast dependency resolution
- Copy `pyproject.toml` + `uv.lock`, install deps (cached layer)
- Copy application code
- Non-root user for runtime
- Expose port 8000

---

## 5. Docker Compose

Services:

| Service        | Image/Build       | Purpose                          |
|----------------|-------------------|----------------------------------|
| `api`          | `./backend`       | FastAPI dev server (auto-reload) |
| `celery-worker`| `./backend`       | Celery worker (auto-reload)      |
| `postgres`     | `postgres:17`     | Database                         |
| `redis`        | `redis:7-alpine`  | Celery broker + result backend   |

Compose features:
- YAML anchors for shared env vars (`&backend-env`) and common service config (`&backend-common`)
- Named volumes: `postgres_data`, `redis_data`
- Host bind-mount `./media` into api + worker containers at `/app/media`
- Dev bind-mount of `./backend/app` for hot-reload on both FastAPI and Celery worker
- `watchfiles` for Celery worker auto-reload on code changes

## 6. File Serving

- FastAPI's `FileResponse` and `StreamingResponse` for serving media files
- Mount `/app/media` as a volume shared between api and worker containers
- Static file mount via `StaticFiles` for direct file access if needed

## 7. Makefile

All commands run through `docker compose`. Key targets:

```
make build          # docker compose build
make up             # docker compose up -d
make down           # docker compose down
make logs           # docker compose logs -f
make shell          # docker compose exec api bash
make test           # docker compose run --rm api pytest
make lint           # docker compose run --rm api sh -c "black --check . && isort --check . && flake8"
make format         # docker compose run --rm api sh -c "black . && isort ."
make migrate        # docker compose run --rm api alembic upgrade head
make migration      # docker compose run --rm api alembic revision --autogenerate -m "..."
```

---

## 8. CLAUDE.md

Key rules for AI-assisted development:
- **NEVER** run `python` or `python3` directly — always use `docker compose run` or `docker compose exec`
- Use `docker compose exec` for running commands in an already-running container
- Use `docker compose run --rm` for one-off commands
- Tests are function-based (no classes) using pytest
- All backend commands go through the Makefile or docker compose

---

## 9. Configuration & OpenAPI

- `pydantic-settings` for environment-driven config (`DATABASE_URL`, `REDIS_URL`, `MEDIA_DIR`, etc.)
- OpenAPI docs auto-served at `/docs` (Swagger UI) and `/redoc`
- API prefix: `/api/v1`
